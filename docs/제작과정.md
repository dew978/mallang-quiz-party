# 제작 과정

2026-11-04 새벽, "초등 전 학년이 쓸 복습 3D 게임을 기획부터 끝까지 알아서 만들어 달라"는 요청 하나로 시작했다.
Claude Code가 기획 → 에셋 생성 → 구현 → 자동 점검 → 다듬기를 혼자 진행했고, 사람은 결과만 받았다.

## 1. 기획 전에 한 일 (00:30~00:45)
- 지난 게임(Q-레이서, 호박 저택 탈출, 액션 RPG 등) 대화 기록에서 **사용자가 직접 요청한 수정사항**을 모두 뽑아 읽었다.
  예: 타이틀 버튼은 가운데 위아래, 3지선다는 정사각형 칸, 보기에 번호 붙이지 않기, 문제 글은 굵지 않게, 입체 버튼,
  캐릭터 눈에 동공, 모자는 따로 씌우기, 부딪히면 튕기기, 문제 중복 줄이기, 저사양 태블릿, 일시정지·전체화면·처음으로.
- Q-레이서의 문제은행(4,778문항 + 수학 생성기)과 에셋 파이프라인 스크립트, 호박 저택 탈출의 검증된 PeerJS 연결 코드를 다시 쓰기로 했다.
- 지난 게임과 장르가 겹치지 않게(레이싱·술래잡기·포격·탁구·탐험) **여럿이 함께 하는 장애물 파티 게임**으로 정했다. 캐릭터·맵·규칙은 모두 새로 만들었다.
- 기획서: [../기획서.md](../기획서.md) (학습 원칙, 라운드 4개, 조작, 화면 흐름, 피드백 체크리스트, 검증 계획)

## 3. 엔진 (00:50~01:30)
- 물리 엔진 없이 직접 만든 캐릭터 물리(상자·원기둥·부채꼴 발판, 움직이는 발판, 튕김, 코요테 타임, 다이브).
- 말랑이는 TRELLIS 몸통 하나 + 코드로 붙인 손·발. 뼈대 없이 상태별로 몸을 찌그러뜨리고 손발을 흔든다.
- 하늘·구름·젤리 바다 셰이더, 사탕 줄무늬 발판, 색종이·물보라 파티클, 화면 흔들림.

## 4. 라운드와 자동 점검 (01:30~03:10)
라운드마다 봇이 끝까지 혼자 하게 한 뒤(`?play=라운드&demo`, 숨긴 창에서도 시간을 빨리 돌리는 `__app.step`)
떨어진 자리를 기록해 원인을 찾았다.
- 정답 문 대시: 회전 막대에 맞은 봇이 계속 떨어짐 → 원인은 **여럿이 난간 옆에서 밀치면 얇은 충돌판을 뚫고 밖으로 밀려나는 것**. 난간 충돌판을 바깥쪽으로 두껍게.
- 움직이는 발판 구간: 봇이 줄줄이 떨어짐 → 원인은 **빠르게 착지하는 순간을 발판 옆면 충돌로 계산해 옆으로 튕겨 내던 물리 버그**. 고친 뒤에도 아이들에게 어렵다고 보고 고정 징검다리 2줄 + 넓게 움직이는 발판 1줄로 바꿈.
- 결승 슈퍼 점프가 짧게 떨어짐 → 착지 처리 순서가 슈퍼 점프 상태를 덮어쓰던 것. 점프대 호출을 상태 처리 뒤로 옮기고, 날아가는 중에는 서로 부딪히지 않게.
- 젤리 발판: 부채꼴 회전 방향(three.js 회전과 각도 기준) 부호를 맞춤.
- 바다 색이 너무 분홍이라 보기 색과 겹쳐 하늘색 탄산 젤리로 바꿈.

## 5. 화면 점검과 다듬기 (03:00~03:40)
- 타이틀 → 학년 → 학기 → 과목 → 메뉴 → 고르기 → 파티 → 중간 순위 → 결과를 1280×800, 1024×768(터치)에서 찍어 보며 고침.
- 모드 카드: 이모지 대신 **게임 엔진으로 무대를 찍은 사진**(`round_*.jpg`). 캐릭터·모자 카드도 게임 속 모델을 그대로 찍음.
- 1024 폭에서 문제 카드와 라운드 이름이 겹쳐 왼쪽 위를 세로 배치로. 이전 라운드 순위 표시가 남던 것 지움. 결과에 시상대 추가.

## 6. 멀티플레이 (03:10~03:30)
호박 저택 탈출의 `net.js`(끊김 재접속, 큰 메시지 나누기, 판 확인)를 가져와 대기실·경기 동기화를 붙였다.
두 탭으로 초대 링크 입장 → 같은 문제 → 같은 자리의 풍선(같은 씨앗) → 풍선 터뜨림·별 동기화 → 방장이 끝 결정 → 양쪽 결과까지 확인.

## 7. 마지막 점검
봇이 파티 쇼 전체(4라운드, 22문제)를 오류 없이 끝까지 진행. 점검 중 바뀐 저장 데이터는 지움.

## 8. 플레이 피드백: 카메라가 장애물에 걸림
- 증상: 정답 문을 지나면 카메라가 벽에 걸린 것처럼 벽·문제판이 화면을 덮음.
- 원인: 카메라에는 충돌이 없었다. 카메라 높이(6.4)가 문제판 높이(4.7~7.0)와 겹쳐서, 캐릭터가 벽을 지나면 벽이 카메라와 캐릭터 사이에 끼고 카메라가 문제판을 그대로 뚫고 지나갔다.
- 자세한 내용·전후 사진: [수정기록.md](수정기록.md)
- 고침: `js/engine/occlusion.js` — 매 프레임 카메라→내 말랑이(몸통 4점)와 카메라 바로 앞으로 광선을 쏴서, 맞은 무대 덩어리(문 벽 한 줄, 기둥, 블록…)를 카메라에만 안 보이게. 충돌체·그림자는 그대로. 회전 막대·추 공·풍선·왕관·동전은 숨기지 않음(`camKeep`). 프레임당 약 0.1ms.

## 9. 저화질에서 모델이 검게 나오던 버그
- 모델(GLB)에 법선이 없어 GLTFLoader가 flatShading을 켜 두는데, 저화질용 Lambert 재질로 바꿀 때 이걸 빠뜨려 말랑이·모자·소품이 새까맣게 나왔다. 터치 기기 기본이 저화질이라 태블릿에서 보였을 버그. `js/engine/assets.js`에서 설정을 옮기도록 고침. 자세한 내용: [수정기록.md](수정기록.md)
